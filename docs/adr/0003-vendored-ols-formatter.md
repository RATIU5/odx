# The `format` rule uses OLS's printer, vendored

odx checks format against OLS's odinfmt printer, vendored into odx at a pinned commit with a fixed config, rather than writing its own printer or calling the team's odinfmt. The team formats with odinfmt, so both must produce the same output, and CI results must not depend on which odinfmt a machine has installed. odx reports differences and never rewrites code, so there is no `odx fmt`.

Amended 2026-10-04: in the odx repo itself, `mise run fmt` prints with the vendored printer, so odx's self-check doesn't depend on the odinfmt a developer has installed. Teams that use odx still format with odinfmt at OLS commit `dd0f85d` and odx's fixed config, which `odinfmt.json` at the root of the odx repo holds for them to copy. odx still ships no format command.

Amended 2026-10-07:

- **Fixed config.** odx prints with one config and ignores any `odinfmt.json` in the checked repo. The values are `character_width` 100, `spaces` 4, `tabs` true, `tabs_width` 4, `brace_style` `_1TBS`, `newline_style` LF, `newline_limit` 1, `sort_imports` true, `convert_do` false, `indent_cases` false, `inline_single_stmt_case` false, `spaces_around_colons` false, `space_single_line_blocks` false, `align_struct_fields` true, `align_struct_values` true, `align_struct_declarations` false, `align_constant_definitions` false, `align_comments` false, `multiline_composite_literals` false and `preserve_struct_blank_lines` false. The parser flags are `{.Optional_Semicolons}`, as OLS's `format.odin` uses.
- **One print.** odx prints each file once and compares the print with the file byte for byte. A file that differs gets one `format` finding at the first differing line. odx never prints the output again. The printer isn't idempotent on every file, so a file can get the finding again after one odinfmt run.
- **Child processes.** The printer runs in child `odx` processes, one file per child, so a print that crashes or hangs ends its child and never `odx check`. A printer crash on a file is a `format` finding on that file, and the rest of the result still prints. A child that runs past 120 s is the error `format-timeout`, and a child that odx can't start or wait for, or whose result odx can't read, is the error `format-failed`.
- **Release statement.** The printer is OLS's `src/odin/printer/document.odin`, `printer.odin` and `visit.odin` at commit `dd0f85d31c91e9d04202cc422288d15b52206474`, with OLS's MIT `LICENSE` beside them. The copy carries one local change: each file starts with `#+vet !unused !shadowing`. Each release states the OLS commit and the compiler it builds the printer with, `dev-2026-09-nightly:a2fb372`, in `odx/ols_printer/README.md`, and an `#assert` on `ODIN_VERSION_HASH` stops a build with any other compiler. Changing the OLS commit or the build compiler changes results, so it ships under a higher rule set.

Amended 2026-10-13: odx 0.2.0 builds the printer, still OLS commit `dd0f85d31c91e9d04202cc422288d15b52206474`, with the compiler `dev-2026-10-nightly:84bc3fc`, and `odx/ols_printer/README.md` and the `#assert` on `ODIN_VERSION_HASH` name that compiler. The new build compiler changed `format` and `parse-unsupported` results, among them that a triple-quoted string now parses and prints, so the change shipped as rule set 2. odx 0.2.0 runs rule set 2 only.
