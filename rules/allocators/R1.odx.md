The directive is the whole odx rule. Leading comments are allowed. By default it
applies to pure and service roles; `odin.explicit_allocators` can extend it to all
roles or turn it off. A reasoned `odx:ignore-file allocators/R1` can document an
intentional file exception. Using scratch memory or replacing context alone does
not exempt a file.

The compiler rejects affected calls that omit allocator parameters, including
`make([dynamic]int)`. It accepts `append` using a container's stored allocator
and APIs such as `fmt.tprintf` that allocate scratch memory internally. Explicit
`context.allocator` arguments are allowed. No ownership or lifetime is proved.

```odin fires
double :: proc(x: int) -> int {
	return x * 2
}
```

```odin silent
#+vet explicit-allocators
double :: proc(x: int) -> int {
	return x * 2
}
```
