---
id: R4
class: errors_or_return
statement: Handle an error where it occurs when you can; when a package's operations genuinely chain, prefer or_return over hand-written `if err != nil { return }`.
why: "'You make your mess; you clean it.' Local handling is the default; or_return is a per-package tool ('when a package needs it, it REALLY needs it') that keeps a chained happy path linear."
severity: warning
instead_of: Blanket or_return everywhere, or blanket hand-written if err != nil blocks.
evidence: "'You make your mess; you clean it' (Exceptions); 'when a package needs it, it REALLY needs it' (Value Propagation Part 2)."
cost: A judgement per package about whether its operations chain; advisory, so a reviewer decides.
blocking: false
check: { kind: example }
---

Advisory. The hand-written form says the same thing in four lines that `or_return` says in one token.

```odin prelude
Error :: enum {
	None,
	Bad,
}

@(require_results)
step :: proc(x: int) -> Error {
	return .Bad if x < 0 else .None
}
```

```odin fires
@(require_results)
run :: proc(x: int) -> Error {
	err := step(x)
	if err != .None {
		return err
	}
	return step(x + 1)
}
```

```odin silent
@(require_results)
run :: proc(x: int) -> Error {
	step(x) or_return
	return step(x + 1)
}
```
