---
id: R5
class: errors_cross_package
statement: An exported procedure's error result is this package's own Error type; a dependency's error is translated at the boundary, never passed through.
why: "'I am not against error value propagation within a library, but I am pretty much always against it across library boundaries.' A foreign error is a degenerate state with high entropy and a lack of specific information for this package's callers."
severity: error
instead_of: Returning os.Error, mem.Allocator_Error or another package's Error straight from your exported API.
evidence: Callers of this package then switch on a type they did not import for that purpose, and every new variant upstream is a silent new failure mode downstream.
cost: One conversion per boundary proc, and an Error variant that names the upstream failure.
blocking: true
check: { kind: foreign_error_type, result_type_suffix: ["Error"] }
---

The boundary is the package. Inside it, propagate freely; across it, translate.

```odin fires
import "core:os"

@(require_results)
read :: proc(path: string) -> (data: []byte, err: os.Error) {
	return os.read_entire_file(path, context.allocator)
}
```

```odin silent
import "core:os"

Error :: enum {
	None,
	Read_Failed,
}

@(require_results)
read :: proc(path: string) -> (data: []byte, err: Error) {
	d, oerr := os.read_entire_file(path, context.allocator)
	if oerr != nil {return nil, .Read_Failed}
	return d, .None
}
```
